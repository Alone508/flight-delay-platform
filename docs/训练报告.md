## 1. 任务定义

### 1.1 业务目标

对**计划起飞前**可获得的航班、机场、航线、天气与历史运行信息建模，预测该航班到达延误是否达到 15 分钟，用于：

- 高风险航班排序与提前干预；
- 大屏展示高风险航班与模型指标；
- 课程项目中 Spark SQL / DataFrame / MLlib 的完整演示。

### 1.2 标签

\[
label = \begin{cases}
1, & arr\_delay \ge 15 \text{ 且 } cancelled=0 \\
0, & arr\_delay < 15 \text{ 且 } cancelled=0
\end{cases}
\]

- 取消航班不参与训练与测试；
- `arr_delay` 为空的行不参与训练与测试。

### 1.3 评估指标

- 主指标：**AUC**（排序能力，阈值无关）；
- 辅助：Accuracy、weighted F1、Precision/Recall（label=1）、混淆矩阵；
- 业务补充：高风险 Top-K 排序（前端只展示 Top 5000）。

> 注意：测试集正例率约 23%，多数类基线 Accuracy 约 76.98%。Accuracy 很容易被负类主导，不能单独作为优化目标。

## 2. 数据与预处理

### 2.1 原始数据

- 来源：Kaggle *Flight Delay and Cancellation Dataset 2019–2023* 的 `flights_sample_3m.csv`；
- 规模：**3,000,000 行，32 列，约 586 MB**；
- 日期范围：**2019-01-01 ~ 2023-08-31**；
- 机场：380 个（出发/到达并集）；
- 航司：18 家；
- 原始统计：取消 79,140 行，`arr_delay >= 15` 约 533,863 行。

### 2.2 DWD 清洗

离线作业：[spark/batch/clean_dwd.py](../spark/batch/clean_dwd.py)

处理内容：

1. `CRS_DEP_TIME` 是未补零的整数（`7`、`954`、`1155`），统一 `lpad` 到 4 位 HHMM；
2. 过滤非法时间（小时 ≥ 24、分钟 ≥ 60、非 4 位数字）；
3. `FL_DATE` 转 DateType，增加 `dep_hour`、`month`、`day_of_week`（ISO：1=周一）、`stat_month`、`dt=YYYYMMDD`；
4. 过滤：
   - `|dep_delay| > 1440` 或 `|arr_delay| > 1440`；
   - `distance <= 0` 或 `distance >= 10000`；
   - `origin/dest` 长度不为 3；
5. 去重键：`fl_date + airline_code + fl_number + origin + crs_dep_time`；
6. 输出 Parquet + Snappy，按 `dt` 分区到 HDFS `/flight/dwd/flight/`。

结果：

| 项目 | 值 |
|---|---:|
| DWD 行数 | **2,999,864** |
| 去掉的重复行 | 136 |
| 日期范围 | 2019-01-01 ~ 2023-08-31 |
| 日分区数 | 1,704 |

### 2.3 时间切分

采用时间切分，避免随机切分造成未来信息泄漏：

| 数据集 | 时间范围 | 行数 |
|---|---|---:|
| 训练集 | 2019-01-01 ~ 2021-12-31 | **1,791,569** |
| 验证集 | 2022-01-01 ~ 2022-12-31 | **667,726** |
| 测试集 | 2023-01-01 ~ 2023-08-31 | **454,373** |

DWD 总行数 2,999,864 与三集合计 2,913,668 的差值来自取消航班和 `arr_delay` 为空的行（不参与 ML）。

### 2.4 类别不平衡

测试集标签分布（由最新模型混淆矩阵反推）：

| 标签 | 数量 | 占比 |
|---|---:|---:|
| 正例（延误 ≥ 15） | 104,619 | **23.03%** |
| 负例（未延误） | 349,754 | 76.97% |
| 合计 | 454,373 | 100% |

多数类（全猜准点）的 Accuracy 为 **76.97%**。因此模型 Accuracy 只有明显高于 76.97% 才具有分类意义；更应关注 AUC 与正类 Recall/Precision。

## 3. 特征工程

### 3.1 特征总览

类别特征（5 个）：

```text
airline_code, origin, dest, month_s, day_of_week_s
```

数值特征（27 个）：

| 类别 | 特征 |
|---|---|
| 计划/航班 | `dep_hour`, `distance`, `crs_elapsed_time` |
| 日历 | `is_weekend`, `is_holiday`（美国主要节假日 2019–2023 共 40 天） |
| 机场拥堵 | `origin_hour_traffic`, `dest_hour_traffic`（同机场同小时计划航班数） |
| 目标编码 | `airline_rate`, `origin_rate`, `dest_rate`, `route_rate`, `airline_origin_rate`, `airline_month_rate`, `origin_month_rate`, `airline_route_rate`, `origin_dow_hour_rate` |
| 时间序列 | `origin_prev_day_rate`, `airline_prev_day_rate`, `origin_prev_dep_delay` |
| 起飞机场天气 | `weather_visib`, `weather_wind`, `weather_precip`, `weather_cat` |
| 到达机场天气 | `dest_visib`, `dest_wind`, `dest_precip`, `dest_cat` |

`weather_cat` / `dest_cat` 映射：VFR=3、MVFR=2、IFR=1、LIFR=0，缺失=-1。

### 3.2 目标编码（Target Encoding）

对类别组合计算历史延误率，并使用平滑：

\[
rate(c) = \frac{\sum_{i \in c} label_i + \alpha \cdot global\_rate}{count(c) + \alpha}
\]

- `global_rate` 只由训练集（2019–2021）计算；
- 默认 `alpha=20`；`airline_route_rate` 使用 `alpha=30`；`origin_dow_hour_rate` 使用 `alpha=50`；
- 编码表只使用训练集，验证/测试与训练集 join；
- 未见类别回退到 `global_rate`；
- 为避免重复计算，代码先 `cache` 训练 base，再只计算一次 9 个编码表，然后分别 apply 到 train/val/test。

编码组合：

| 编码 | 分组键 |
|---|---|
| `airline_rate` | airline_code |
| `origin_rate` | origin |
| `dest_rate` | dest |
| `route_rate` | origin + dest |
| `airline_origin_rate` | airline_code + origin |
| `airline_month_rate` | airline_code + month |
| `origin_month_rate` | origin + month |
| `airline_route_rate` | airline_code + origin + dest |
| `origin_dow_hour_rate` | origin + day_of_week + dep_hour |

### 3.3 时间序列 / 前序航班特征

为避免使用未来信息，只使用预测时刻之前已经发生的数据：

1. **前一日延误率**
   - `origin_prev_day_rate`：同机场前一天的平均 `label`；
   - `airline_prev_day_rate`：同航司前一天的平均 `label`；
   - 通过把日期 +1 后 join 实现，缺失回退 0.18。
2. **同机场前序航班延误**
   - `origin_prev_dep_delay`：同机场、同一天，计划起飞时间在 **前 2–4 小时** 的航班平均 `dep_delay`；
   - Spark Window：`partitionBy(origin, fl_date).orderBy(dep_hour).rangeBetween(-4, -2)`；
   - 不使用 h-1 小时内的航班，避免“同时刻信息尚未产生”的泄漏。

### 3.4 天气特征

历史天气由 [collector/weather_history.py](../collector/weather_history.py) 采集：

- Open-Meteo Archive API；
- 按航班量取 Top **80** 个机场；
- 时间范围 2019-01-01 ~ 2023-08-31；
- 每个机场 40,896 条逐小时记录；
- `timezone=auto`，与机场本地计划时间对齐；
- visibility 从米转换为英里；
- 输出 HDFS `/flight/dwd/weather_hourly/`。

模型使用起飞机场和到达机场的：

- 能见度（`visib`）
- 风速（`wind`，节）
- 降水（`precip`，mm）
- 飞行类别（VFR/MVFR/IFR/LIFR）

> **时间有效性说明**：当前天气是历史实况（reanalysis），而不是起飞前可获得的预报。离线指标可能偏乐观；生产环境应替换为 TAF / 天气预报，或明确把预测时点设为天气实况已发布之后。

### 3.5 明确排除的泄漏字段

以下字段为事后信息，绝不进入特征：

```text
DEP_DELAY, ARR_DELAY, DEP_TIME, ARR_TIME,
TAXI_OUT, TAXI_IN, WHEELS_OFF, WHEELS_ON,
AIR_TIME, ELAPSED_TIME,
DELAY_DUE_CARRIER, DELAY_DUE_WEATHER, DELAY_DUE_NAS,
DELAY_DUE_SECURITY, DELAY_DUE_LATE_AIRCRAFT
```

`DELAY_DUE_*` 只在延误 ≥ 15 分钟时有值，五者之和等于到达延误，属于典型标签泄漏，仅用于离线原因分析。

## 4. 模型与训练

### 4.1 Pipeline

```text
StringIndexer (5 个类别特征, handleInvalid=keep)
  → OneHotEncoder (handleInvalid=keep)
  → VectorAssembler (one-hot + 27 个数值特征)
  → 分类器
```

- LR 额外加 `StandardScaler(withMean=false, withStd=true)`；
- RF / GBT 直接使用 `features`。

### 4.2 模型与超参数

| 模型 | 超参数 | 训练数据 |
|---|---|---|
| LogisticRegression | `maxIter=50`, `regParam=0.01` | 全量训练集 1,791,569 |
| RandomForest | `numTrees=50`, `maxDepth=7`, `maxBins=64`, `subsamplingRate=0.8`, `seed=42` | 40% 样本 |
| GBT | `maxIter=40`, `maxDepth=5`, `stepSize=0.1`, `maxBins=64`, `seed=42` | 40% 样本（最新 717,085 行） |

说明：树模型使用 40% 训练样本是为了在 15 GiB 单机上控制训练时间与内存；LR 使用全量。

### 4.3 阈值调优

- 用 2022 验证集预测概率，按 **label=1 的 F1** 扫描阈值 0.05–0.95（步长 0.01）；
- 在验证集 20% 样本（133,023 行）上计算，减少 driver 内存压力；
- 最新模型选择阈值 **0.17**，验证集 label=1 F1 = **0.4148**；
- 通过 `model.stages[-1].setThreshold(t)` 写回分类器，再在测试集评估与生成预测标签。

### 4.4 模型选择

- 仅按**验证集 AUC**选模型，测试集只用于最终报告；
- 最新训练只跑 GBT，验证 AUC 最高，保存为 `gbt-202611231630`；
- 保存路径：HDFS `/flight/ml/model/gbt-202611231630`；
- 预测结果：HDFS `/flight/dws/predictions/gbt-202611231630`，Top 5000 写 MySQL。

### 4.5 训练资源与运行时间

最新一次训练：

- `spark-submit --master local[4] --driver-memory 3g --conf spark.sql.shuffle.partitions=24`
- 训练期间停止 HBase / Flume / Spark Streaming，释放约 5–6 GiB 内存；
- Spark 版本 3.5.1，Java 8；
- 起止时间约 **16:28:57 → 16:40:43**，总耗时约 **11 分 46 秒**；
- 期间出现 `MemoryStore` 落盘告警，但任务正常完成；
- 模型训练完成后，HBase / Flume / Streaming 已恢复。

### 5.2 最新模型混淆矩阵

测试集 454,373 行，阈值 0.17：

|  | 预测准点 | 预测延误 |
|---|---:|---:|
| **实际准点** | 341,416 (TN) | 8,338 (FP) |
| **实际延误** | 93,764 (FN) | 10,855 (TP) |

由此计算：

| 指标 | 值 |
|---|---:|
| Accuracy | **77.53%** |
| Precision（label=1） | **56.56%** |
| Recall（label=1） | **10.38%** |
| F1（label=1） | **17.54%** |
| weighted F1 | 71.00% |
| AUC | **0.6790** |
| 正例率 | 23.03% |
| 多数类基线 Accuracy | 76.98% |

**关键结论**：Accuracy 77.53% 只比“全猜准点”的 76.98% 高约 **0.55 个百分点**；模型价值主要体现在 AUC 排序能力和高风险 Top-K 列表，而不是 Accuracy。

### 5.4 结果分析

1. **验证/测试 AUC 一致**：0.6779 vs 0.6790，说明时间切分下模型没有明显过拟合。
2. **阈值迁移不完美**：验证集 0.17 阈值下 F1=0.4148，但测试集 label=1 F1 只有 0.1754；2022 与 2023 的分数分布存在漂移。
3. **高精度低召回**：测试集 Precision 56.56%、Recall 10.38%，模型倾向于只对少数高分航班报警；适合 Top-K 风险排序，不适合作为单阈值全覆盖分类。
4. **Accuracy 不是好指标**：正例率 23%，多数类基线 76.98%；当前 Accuracy 77.53% 仅略高。
5. **加训练时间的收益递减**：当前 GBT 只用 40% 训练样本、40 轮迭代；扩到全量/更多轮次的预期提升约 +0.005~0.015，难以单独达到 0.72。

## 7. 局限与风险

1. **缺少最强特征**
   - 没有机尾号/同一架飞机前序航班信息；
   - 没有 NAS / FAA 流量控制、地面停场、GDP；
   - 没有机场跑道构型/实际容量；
   - 这些通常是延误预测中增益最大的数据。
2. **天气时间有效性**
   - 当前使用历史实况，而不是起飞前预报；离线 AUC 可能偏乐观。
3. **数据量**
   - 使用 3M 行样本，不是完整 30M 行数据；
   - 2023 测试集只有 1–8 月，未覆盖全年与极端冬季场景。
4. **模型容量**
   - GBT 只用了 40% 训练样本、40 轮、深度 5；
   - 未做系统性超参数搜索与 rolling-origin 交叉验证。
5. **类别不平衡**
   - 正例 23%，默认阈值/阈值迁移导致 Recall 低；
   - 未做概率校准、类别加权、PR-AUC/Recall@K 评估。
6. **Accuracy 误导**
   - 多数类基线 76.98%，Accuracy 77.53% 不能说明模型好用；
   - 应使用 AUC、PR-AUC、Top-K 指标。

## 8. 优化方向

### 8.1 训练侧（成本低，预期 +0.005~0.015）

- GBT 使用全量训练集（1,791,569 行）而不是 40%；
- `maxIter` 40 → 100~200，`maxDepth` 5 → 6~7，`stepSize` 0.1 → 0.05，`maxBins` 64 → 128；
- 用 2022 验证集做早停（`validationIndicatorCol` / `validationTol`）；
- rolling-origin 验证（2019→2020、2020→2021、2021→2022）；
- 类别加权 / `weightCol`，并做概率校准（Platt/Isotonic）；
- 增加 PR-AUC、Recall@Top-K、Precision@Top-K 评估。

### 8.2 特征侧（中等成本，预期 +0.01~0.03）

- 航司×机场、航司×航线、机场×时段的前序延误（不仅起飞机场整体）；
- 近 7 天 / 30 天滚动延误率；
- 到达机场前序延误、目的地拥堵；
- 机尾号/同一架飞机前序航班延误（需要新数据）；
- NAS/FAA ground stop、GDP、跑道关闭；
- 预报天气/TAF 替换历史实况；
- 节假日/学校假期/大型活动。

### 8.3 模型侧

- LightGBM / CatBoost / XGBoost：对高基数类别和缺失值更友好，通常比 MLlib GBT 更强、更快；
- GBT + LR/RF 集成/stacking；
- 直接回归 `arr_delay` 分钟数，再按业务阈值分档；
- 预测严重延误（≥60 分钟）或风险分层。

### 8.4 数据侧（高成本，预期 +0.02~0.05）

- 使用完整 30M 行数据与更多年份；
- 接入真实航班动态、机尾号、NAS、机场运行数据；
- 这些是冲击 0.72 的主要途径。

> 结论：仅靠加大训练时间，较现实的 AUC 区间是 **0.68–0.70**；要稳定达到 0.72，需要引入前序航班/尾号、NAS 流控或预报天气等新数据。
